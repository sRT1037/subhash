Multiagent Multi-Team

This is the setup I built at Rubrik for using agents on my own, and how I think it should extend once you go from one person to a team of them. I wouldn’t call it efficient, and I wouldn’t claim it works for everyone — it’s just what worked for me, and the version here is the base case that later iterations build on.

The single-person setup

The core problem is that Claude has no long-term memory — it tends to hallucinate or guess rather than recall anything from a previous session. So instead of relying on the model to remember, I built memory outside it: an Obsidian vault structured as a knowledge graph, which accumulates the research and findings from every Claude session I run.

On top of that vault sit two agent pools. A temporary agent pool — agents spun up for a specific task and discarded once it’s done — and a permanent agentic pool of agents that persist across sessions and carry ongoing responsibilities. Both pools read from and write back into the same Obsidian vault, so whatever a temporary agent discovers in the course of a one-off task still lands in the same long-term graph that the permanent agents draw on later. The person sits at the top, dispatching into these two pools; everything either pool learns flows down into the vault, and the vault itself is really an accumulation of graph vaults built up over many Claude sessions, not a single flat notes file.

Within a subteam

The same pattern repeats per person once you’re working with others, not just as one agent stack per individual. Each person in a subteam runs their own copy of this setup — their own temporary and permanent agent pools, writing into their own Obsidian vault. What changes is that those individual vaults aren’t siloed: they feed into a common Obsidian graph vault shared across the subteam. So person 1’s research and person 2’s research stay separately attributable in their own vaults, but both converge into one shared graph that the whole subteam can draw context from, instead of everyone rediscovering the same things independently.

Across subteams

This nests one more level up. Each subteam — built out of individual people, each with their own agent pools and vaults, rolling up into that subteam’s common graph vault — is itself just one node feeding a level higher. Subteam A’s graph vault and subteam B’s graph vault both roll up into a single organisation graph vault. The structure is the same recursive shape at every level: individual vaults roll up into a subteam vault, and subteam vaults roll up into an org-wide one, so knowledge accumulated by one person on one subteam is, in principle, reachable by anyone else in the organisation without them having to redo the research themselves.

What I like about this shape is that it doesn’t require redesigning anything as you scale — the same person → agents → vault unit is the building block whether you’re one person, a subteam, or an org, you’re just adding another rollup layer on top.
